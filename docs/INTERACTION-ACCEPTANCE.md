# 交互验收

0.2.5 新增可重复的浏览器集成验收。它与原有宿主 / 客户端进程内测试互补，不代表已经验证完整 DSH 桌面程序。

0.2.6 本轮在 Windows Chromium 通过 8 项浏览器夹具验收，新增宿主轻量模式结果的校验、回填与还原。另有组件回归验证完整引用元数据的单次原子坐标替换、身份保留和拒绝跨引用的改写；浏览器夹具只验证元数据不完整时禁用入口，不把 textarea 冒充原生引用节点。

## 自动验收

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

Playwright 为精确版本的开发依赖，不进入插件运行依赖或发布 tarball。0.2.8 在浏览器内存中载入打包后的真实 ComposerBooster 插槽组件；以固定结果代替模型，以标准 textarea 编辑事务代替 DSH 富文本编辑器，不访问账户或用户会话，也不依赖回环服务器。测试报告和失败 trace 位于被 Git 忽略的 test-results/。

0.2.8 Windows / Chromium 10 项通过：

| 场景 | 验证内容 |
| --- | --- |
| 回填与还原 | 写回后恢复输入焦点；还原恢复原文；没有自动发送 |
| 键盘与撤销 | Tab / Enter 激活按钮；ControlOrMeta+Z 撤销 textarea 的浏览器事务 |
| 请求期间编辑 | 返回结果不能覆盖用户新草稿 |
| 组合输入事件 | compositionstart / compositionend 期间禁用新优化及还原；晚到结果不写入 |
| 取消与会话切换 | 晚到结果不替换原稿或新会话内容 |
| 拦截原因与引用 | 具体原因可读；悬停可见多项原因；结构化引用禁用优化 |
| 主题、窄屏与动态效果 | DSH 深色主题标记、320px 宽度、减少动态效果设置 |
| 宿主模式 | 配置轻量模式的结果正确校验、回填和还原 |
| 连接失败 | 固定连接故障保留原稿，同一按钮恢复后可重试；不表示真实断网已验收 |
| 连续润色 | 再次优化使用 light，连续采纳后可还原最初原稿 |

测试在本地遇到一次多进程加载回环页面被环境拒绝访问；改为单个浏览器工作进程后，7 项完整通过。保持 retries: 0，不用重试掩盖失败。CI 新增 Ubuntu / Windows 浏览器任务，远端结果以 Actions 为准。

0.2.8 再次观察到随机场景在 page.goto 阶段报 ERR_NETWORK_ACCESS_DENIED，尚未执行组件操作。将离线夹具改为内存载入后，全部 10 项一次通过；未修改浏览器安全策略或增加自动重试。

## 组词保护边界

工具栏只观察当前页面可编辑元素的组合输入开始 / 结束事件，不读取组词内容、不拦截键盘或发送动作。页面处于组合输入时，本插件保守暂停所有已挂载工具栏的回填和还原，避免覆盖尚未提交的文字；结束后可再次点击优化。原有版本冲突检查仍独立生效。

浏览器事件不等于操作系统候选窗。Playwright 的[键盘文档](https://playwright.dev/docs/api/class-keyboard)说明了其虚拟键盘行为；这里不把非拉丁字符插入或合成 composition 事件当成 Windows / macOS 原生输入法验收。
