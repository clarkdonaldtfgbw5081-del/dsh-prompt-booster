## 当前差异

- 0.1.6 交互入口仍是输入框工具行左侧的小按钮；点击后校验并直接回填原输入框，没有预览弹框。可再次点击取消，也可还原优化前的原稿。
- 默认超时是 15 秒，尚未证明设计中的延迟目标。
- 当前快捷入口仅使用草稿，不自动消费文件、附件或完整对话；模式和资料契约保留在引擎与 RPC 层。
- 含结构化引用时禁用优化；请求中途加入引用也阻止回填，防止破坏引用身份。
- 不向主 Agent 发送“优化”指令，也不在发送链路中隐式重写消息。
- 原稿和预览只存在客户端操作状态；实际模型请求另按 DSH 宿主要求记录审计。
- 事件统计默认只进有界内存。自有 `feedback` RPC 将客户端采纳、编辑、还原事件汇总到宿主；未新增 HTTP 入口。会话资源权限由 Gateway 检查。
- `prompt_sent` 仅由实际写入会话的用户消息与采纳稿摘要匹配触发，不再通过输入框清空推断；修改后再发送可能漏计。
- 80 条人工构造样例覆盖路由与守卫回归，不充当真实用户黄金集。真实模型评测会报告覆盖率与回退，尚未运行真实模型评测。

## 0.2.0 六项完善

通过已安装桌面运行时的官方 DeepSeek Account 适配器实测三条人工请求，最终均成功（1745 / 1459 / 821 ms）；样本小，不作质量分数或生产延迟承诺。原生 Settings 使用 `Config.volatile()` 生成表单，允许上下文与明确偏好由宿主 profile 持久化并在下一次请求生效。

上下文只取本会话近期用户文本和显式配置的工作区文件；读取取消、大小、常见凭据、路径边界与端到端来源均有自动化验证。格式与守卫错误最多修复一次，共用原预算。焦点恢复使用原生 `SessionInput.focus()`，回填沿用单步 `InputActions.insertText`，完整桌面快捷键仍待实际交互验收。

## 0.1.9 可靠性修复

使用官方 `prepareCall(config, signal, configure)` 能力元数据选择辅助请求的思考档位；默认输出上限 4096。缺省元数据归一化后仍通过同一严格结果契约；记录安全的结果审计代码。进程内原生宿主测试覆盖档位、上限与截断 finish，未视为真实提供方交互验收。

## 0.1.8 需求匹配改进

保留原输入框内一键回填，不增加优化接口调用次数。宿主和客户端共用意图、预算与守卫规则，按任务选择默认项；新增模块无额外运行依赖。意图识别与偏好守卫是保守的关键词规则，真实模型效果仍需人工评估，不声称完整语义保真。

## 0.1.7 默认方案补齐

网页类标准请求中缺失的技术路线、模块、素材和交付方式由宿主默认方案补齐，标记为可调整选择；模型与客户端使用同一规则核对允许项。已指定要求、方案阶段和真实事实缺口保持原边界。新增契约会随宿主与客户端一同升级，需重启应用加载新版。

## 0.1.6 直接回填

已通过组件测试验证没有弹框或额外文本编辑器，优化成功直接写回草稿，取消或草稿变化时不覆盖；会话切换取消旧请求。原生输入接口仍通过带草稿版本的 `insertText` 和 `persistDraft` 执行回填。未据此声称完整桌面视觉与真实模型流程已通过。

## 0.1.5 客户端注入修复

原生 Cordis 与官方客户端 Gateway 的进程内集成测试已复现并修复 `remote.promptBooster` 缺少注入声明的问题，覆盖优化、反馈和卸载。构建产物也实际执行客户端入口并验证 RPC 与卸载。未将这些检查视为完整桌面安装或真实模型验收；升级包后需重启目标 DSH。
