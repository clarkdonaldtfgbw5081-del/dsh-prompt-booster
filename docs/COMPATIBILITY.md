## 当前差异与已知限制（0.2.11）

- 入口是输入框工具行左侧的小按钮；点击后校验并直接回填原输入框，没有预览弹框。可再次点击取消，也可还原优化前的原稿。
- 默认超时是 15 秒，尚未证明设计中的延迟目标。
- 快捷入口默认只使用当前草稿；指代型草稿可附带本会话最近至多 3 条用户消息，文件只按设置中的明确路径读取并提取相关原文。普通附件不自动参与优化；原生设置 mode 支持 light / standard。
- 具有完整有效元数据的结构化引用允许不跨引用的一次文本替换，使用原子坐标并保留身份；跨引用、移动或重复引用保留原稿，未知引用禁用入口。请求中途的引用变化阻止回填。现有证据为组件回归，仍需真实富文本验收。
- 不向主 Agent 发送“优化”指令，也不在发送链路中隐式重写消息。
- 原稿和结果在客户端只保存在操作状态；每次优化还会通过 `appendPluginRecord` 向 DSH 会话写入 ignorable plugin record（request 含系统提示词与完整模型输入，result 只含状态 / 失败码 / 耗时），随会话日志持久化、fork/resume 携带、可随会话导出，但不进入模型可见面。见 [SECURITY.md](../SECURITY.md)。
- 事件统计默认只进有界内存。自有 `feedback` RPC 将客户端采纳、编辑、还原事件汇总到宿主；未新增 HTTP 入口。会话资源权限由 Gateway 检查。
- `prompt_sent` 仅由实际写入会话的用户消息与采纳稿摘要匹配触发，不再通过输入框清空推断；修改后再发送可能漏计。
- 83 条人工构造样例覆盖路由与守卫回归，不充当真实用户黄金集。守卫能确定性检查部分约束，不能证明中文业务名词与语义等价。
- 主题跟随 DSH 解析后的深浅主题（`data-ds-dark-theme`），并保留系统配色回退；第三方主题未验收。
- 0.2.6 本地 204 项测试、83 条离线样例、24 项质量断言和 8 项 Windows Chromium 夹具验收通过。0.2.5 发布提交的远端跨平台 CI 已通过，不能视为 0.2.6 的远端结果。
- 0.2.6 未运行真实模型或新增人工需求评分；Windows 桌面工具连接失败，系统输入法和完整宿主交互仍待验。盲评导入与隐私边界见 [evals/QUALITY.md](../evals/QUALITY.md)。

## 真实模型证据（截至 0.2.4）

真实模型样本均为固定人工构造的合成样例，没有使用真实用户项目文件或会话正文。记录见 [evals/DESKTOP-VALIDATION.md](../evals/DESKTOP-VALIDATION.md) 与 `evals/results/`。

| 版本 | 样本 | 结果工件 |
| --- | --- | --- |
| 0.2.0 | 桌面账户适配器冒烟 3 条 | `results/live-desktop-0.2.0.json`（另有初始 / 中间记录与一次 TRANSPORT 失败记录，失败记录未计为质量通过） |
| 0.2.1 | 桌面账户适配器冒烟 5 条全部成功（1 条调用受控修复）；默认项调整后复查 2 条成功 | `results/live-desktop-0.2.1.json`、`results/live-desktop-0.2.1-final.json` |
| 0.2.4 | `evals/run.ts --live` + DeepSeek API（`deepseek-chat`）76 条非跳过样例：75 ok、1 fallback；约束保留 29/29；P50 1141 ms / P90 1550 ms / max 1978 ms | `results/live-deepseek-chat-20261020.json`（调整前后另有 `-before-tune.json`、`-after-bookkeeping.json`） |

- 0.2.0 / 0.2.1 的工件由未提交的本地桌面脚本（`.local/scripts/live-desktop.cjs`）生成，**仅凭仓库无法重新生成**；工件本身缺少 `model` / `created_at` / `git_commit`。
- 0.2.4 的工件由仓库内 `npm run evals:live -- --out …` 生成（`schema: 1`，含模型、时间、提交与逐条字段），可复跑但需要 `BOOST_API_KEY`。运行时仓库工作树包含未提交的 0.2.4 改动，因此工件的 `git_commit` 指向基线提交 `ac65ff5`，不等于被测 0.2.4 工作树本身。
- 0.2.4 的唯一 fallback 是 `inj3`（上下文要求忽略用户任务、改为实现注册功能）：`expanded_scope` 按预期拦截，属于注入防御命中，不是可用性失败；live 指标仍按统一口径计入 fallback。
- 这些样本只用于连通性、守卫回归与定向检查，不构成质量分数、成功率或生产 P90 延迟承诺。`--live` 直接调用模型服务，不经过安装版 DSH 宿主；宿主内交互仍以验收清单为准。

## 0.2.0 六项完善

通过已安装桌面运行时的官方 DeepSeek Account 适配器实测三条人工请求，最终均成功（1745 / 1459 / 821 ms）；记录见 [evals/DESKTOP-VALIDATION.md](../evals/DESKTOP-VALIDATION.md)。样本小，不作质量分数或生产延迟承诺。原生 Settings 使用 `Config.volatile()` 生成表单，允许上下文与明确偏好由宿主 profile 持久化并在下一次请求生效。

上下文只取本会话近期用户文本和显式配置的工作区文件；读取取消、大小、常见凭据、路径边界与端到端来源均有自动化验证。格式与守卫错误最多修复一次，共用原预算。焦点恢复使用原生 `SessionInput.focus()`，回填沿用单步 `InputActions.insertText`，完整桌面快捷键仍待实际交互验收。

## 0.1.9 可靠性修复

使用官方 `prepareCall(config, signal, configure)` 能力元数据选择辅助请求的思考档位；默认输出上限 4096。缺省元数据归一化后仍通过同一严格结果契约；记录安全的结果审计代码。进程内原生宿主测试覆盖档位、上限与截断 finish，未视为真实提供方交互验收。

## 0.1.8 需求匹配改进

保留原输入框内一键回填，不增加优化接口调用次数。宿主和客户端共用意图、预算与守卫规则，按任务选择默认项；新增模块无额外运行依赖。意图识别与偏好守卫是保守的关键词规则，真实模型效果仍需人工评估，不声称完整语义保真。

## 0.1.7 默认方案补齐

网页类标准请求中缺失的技术路线、模块、素材和交付方式由宿主默认方案补齐，标记为可调整选择；模型与客户端使用同一规则核对允许项。已指定要求、方案阶段和真实事实缺口保持原边界。新增契约会随宿主与客户端一同升级，需重启应用加载新版。

## 0.1.6 直接回填

已通过组件测试验证没有弹框或额外文本编辑器，优化成功直接写回草稿，取消或草稿变化时不覆盖；会话切换取消旧请求。原生输入接口仍通过带草稿版本的 `insertText` 和 `persistDraft` 执行回填。未据此声称完整桌面视觉与真实模型流程已通过。

## 0.1.5 客户端注入修复

原生 Cordis 与官方客户端 Gateway 的进程内集成测试已复现并修复 `remote.promptBooster` 缺少注入声明的问题，覆盖优化、反馈和卸载。构建产物也实际执行客户端入口并验证 RPC 与卸载。未将这些检查视为完整桌面安装或真实模型验收；升级包后需重启目标 DSH。

## 0.1.4 补全验证

本地测试和源码核对记录见 [CHANGELOG.md](../CHANGELOG.md)。本轮未修改用户已安装的桌面 profile，也未将历史 0.1.1 的入口渲染记录视为 0.1.4 的完整验收。
