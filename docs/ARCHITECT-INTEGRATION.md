# Architect 方法整合说明

版本：方法引入 0.2.1；文档更新 0.2.4。查阅日期：2026-10-20。

用户确认吸收 https://github.com/architect/architect 的方法，按任务选择方案。该项目是 AWS Serverless 开发框架，本次没有将其误作通用 SKILL.md，也没有安装框架运行时、复制仓库源码或执行远程指令。规则是结合提示词插件需求自行编写的适配方法，不表示上游为本插件背书。

## 方法映射

| 官方方法 | 插件应用 | 边界 |
| --- | --- | --- |
| 项目清单表达应用所需资源 | 识别任务实际所需能力；Architect 任务可补资源清单 | 不照搬示例资源，资料提及不等于任务要求 |
| 按事件来源及职责组织处理逻辑 | 接口、持久化、后台任务、实时通信按需提供边界与验证指引 | 只匹配当前草稿正向需求；否定项不触发 |
| 本地开发与沙箱验证 | 方案说明验证方法；实施任务交付相关代码及验证 | 方案阶段不变成执行 |
| 不同发布环境 | 用户已要求部署时区分验证与目标环境 | 不由“开发网站”擅自引入上线 |

独立页面优先轻量方案、沿用现有项目、当前要求优先、受控上下文与来源守卫是本插件的适配策略，不是对上游原文的逐字引用。

## 实现与使用

`src/core/strategy.ts` 本地选择一般任务、解释、诊断、现有项目修改、页面、应用或其他软件指引。写作、研究、分析和轻量模式不套开发模板；创建带数据库的应用仍识别为开发。`solution_strategy` 随原有模型请求发送，不增加专门选型调用。

只有适用的软件任务且原稿明确使用 Architect、指向 Architect 项目或清单时才启用专项指引。AWS 或 Serverless 本身不会自动选中框架，研究比较、否定表达和一般角色称呼不应触发。辅助指引不能覆盖原稿、授权新增技术、猜测项目事实或增加长度上限。

新页面继续使用已有可追踪默认项；带服务能力的应用不强行使用静态页面技术路线，不默认加素材图片。明确使用 Architect 的新任务默认交付可包含资源清单和本地沙箱验证。现有项目修改仍限定范围。客户端与宿主继续共用默认项和守卫逻辑。

文件设置中明确列出的 `app.arc` 仅作为工作区文本读取，仍受大小、路径、敏感文本和总字符限制。不会扫描整个项目、执行清单或自动部署。

## 验证与限制

自动化测试与离线样例通过（数量见 README）。真实桌面模型首轮 5 条固定样例全部成功，其中 1 条调用受控修复；服务默认项调整后复查相关 2 条成功。记录见 `evals/DESKTOP-VALIDATION.md`。0.2.4 另用 DeepSeek API（`deepseek-chat`）跑 76 条非跳过 live 样例（75 ok，1 条注入防御）；0.2.2 / 0.2.3 尚无真实模型样本。

有限文本规则可能误判复杂否定、间接指代或混合任务。模型以当前原稿为准，用户仍可编辑或还原。小样本结果不是大规模盲评，不能保证下游生成效果或实际云环境兼容性。方法规则随插件版本发布，不会在优化时自动下载仓库内容。
