# 需求匹配的人工验收

当前离线回归验证规则和脚本化输出，不代表真实模型已获得质量分数。真实输出可用相同原稿分别在旧版与新版生成，隐藏版本后请用户按以下标准比较，保留失败案例进入回归集。

| 观察点 | 合格条件 |
| --- | --- |
| 目标 | 仍在完成用户原本要做的事，没有把写文案变成开发页面 |
| 范围 | 局部修改保持局部，没有新增不需要的完整系统或业务模块 |
| 阶段 | 区分仅给方案、等待确认、只分析以及先分析后实施 |
| 要求 | 风格、受众、语言、输出格式、路径、数字和禁止项得到保留 |
| 默认补全 | 缺失选择与实际任务相关，作为默认方案表述，不冒充已知事实 |
| 可执行性 | 下游执行者能辨认要交付什么；没有用泛泛形容替代具体任务 |
| 简洁性 | 每项补充有用途，短请求不被无关模板淹没 |

建议覆盖：风景展示页、登录页、管理后台、作品集、修改现有排版、网页文案、故障定位、解释性提问、研究比较、数据分析、面向初学者的友好说明，以及含明确字数和交付阶段的请求。

若关键要求丢失、阶段改变或事实被编造，即使表达更流畅也应判为失败。另行记录模型路由、版本、延迟和失败状态；不要只比较成功样本，也不要把一次较好输出当成整体质量提升的证明。
